Jail

題目給了一個網址，點進去是：

可以看到，他會把 ()_[]{}.@# 給過濾掉，而且過濾前會先做 NFKC Unicode 正規化，所以靠全形字元繞過行不通。

不過 Python 的 source encoding 機制其實只用正則 coding[:=]\s*([-\w.]+) 去掃前兩行，只要匹配到就會用對應 codec 先解碼整個檔案，不要求一定要寫在 # 註解裡。第一行寫成 -Wignore coding: unicode-escape 就能觸發 encoding 切換，後續整個檔案會先用 unicode-escape 解碼，payload 裡的 \x28、\x29、\x2e 在 tokenize 之前就被還原成 (、)、.，完全繞過過濾。

Exploit:

FLAG: AIS3{5H3_BA_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_A_NG!}

Reverse

tetris，簡單

題目給了一個檔案，裡面有一堆東西，總之是個 statically-linked stripped ELF64，跑起來是可以玩的終端 Tetris，控制 WASD + Q 旋轉。

阿剛剛說到有很多東西，但真正重要的就是

要在程式跑起來後用 gdb dump，因為 fn_table 在 0x1aa8aa0 有 100000 個 slot（每個是 8 bytes 的函式指標，共 800000 bytes），靜態看大部分是 no-op decoy，runtime 才會被 patch 成真的 function。

filter 出 pointer 落在 0x15c2000 - 0x15c4000 的 entry 就拿到 26 個真的 state。

接著看 input handler 0x15c3798 用 key - 'A' 查 jump table，發現除了 WASD/Q 之外，P 也有對應分支但題目沒講，跟著走到 0x15c31。

0x15c31 呼叫 0x15c1a6e 看到 0x811c9dc5 (FNV-1a offset basis)、0x01000193 (FNV prime)、0x41c64e6d / 0x3039 (glibc rand LCG)。再看 0x15c1c61 是標準ㄉ RC4。

追一下 FNV-1a 的輸入來源，發現它吃的是 0x13371e0 開頭的記憶體，那邊放著 4×10 的 board state（每個 cell 是 4-byte int，row stride 40 bytes），整張 grid hash 完當 RC4 key 用。ciphertext 則在 0x16a5130，長 28 bytes。

Exploit:

FLAG: AIS3{T3tr1s_P4tt3rn_M4st3r!}

題目給了檔案，裡面有兩個東西，一個是 luac_stripped.exe 跟 secret.luac。

先看看 secret.luac 的標頭，是 1b 4c 75 61 51，是 Lua 5.1 的 bytecode，但直接用一般的 luac5.1 -l secret.luac 會炸，opcode 看起來也不正常，所以就去看題目給的 luac_stripped.exe。

分析 luac_stripped.exe 後發現，他是改過的 Lua 5.1 loader。正常 Lua 5.1 的 instruction 是 32-bit，最低 6 bits 是 opcode：

opcode = instruction & 0x3f;

還原公式是：

Pwn

std::print(“Hello, World”) revenge

題目給了一個資料夾，裡面有 Dockerfile、docker-compose.yml、xinetd 設定，以及 share/ 底下的 chall binary、Makefile、run.sh。

看 Makefile：

CXXFLAGS = -std=c++23 -Wall -Wno-stringop-overflow -no-pie -fno-stack-protector -Wl,-z,relro,-z,now

C++23、no PIE、沒 canary、Full RELRO。

main 會先呼叫 load_flag() 把 flag.txt 讀到 .bss 的 0x427040，然後 show_number() 用 std::print("Value: {2}\n", ...) 印一個 Value: 1337 出來，最後 while(1) Question();。std::print 本身是編譯期 type check，沒有 format string 漏洞。

真正的洞在 Question()：

0x50 的 buffer 讀 0xe0 byte，標準 BOF。然後 main 是 while(1) Question();，可以一直觸發。

Flag 在程式啟動時就被 load_flag() 讀到 .bss 的 0x427040，目標是把它印出來。

問題是這個 binary 找不到乾淨的 pop rdi ; ret，能用的 popper 只有：

0x405d7f: pop rbx ; pop r12 ; pop rbp ; ret

其他 gadget 幾乎都長這樣：

mov rdi, rax ; call ... ; leave ; ret

leave ; ret 要 rbp 控制才能跑，所以這題要的是 rbp 控制，不是傳統的 ret address 鏈。

翻 std::vprint_nonunicode 的內部，在 0x404558 找到：

整段等於 fwrite(*(rbp-0x1b0), 1, rbx, *(rbp-0x1f8))。

stdout 的 GOT 在 0x427020，解 rbp - 0x1f8 = 0x427020 得 rbp = 0x427218。這時 rbp - 0x1b0 = 0x427068，把 flag 地址塞進去就好，兩個位置都在 .bss 可寫。

Question() 結尾 leave ; ret 等於 rsp = rbp ; pop rbp ; ret。把 saved RBP 蓋成 P，return 後 rsp = P+8。

關鍵是可以 ret 回 Question 自己的 body，跳過 prologue 落在 0x4035dc：

從 0x4035dc 進去保留設好的 rbp，又是一次 0xe0 byte 的 read 到任意位置。一個 BOF 變無限次的任意位址寫。

'y' + 'A'*79 + p64(0x427088) + p64(0x4035dc)

leave/ret 後 rsp = 0x427090，下一次 read 寫到 0x427038。

從 0x427038 開始寫：

  1. 在 0x427068 塞 0x427040（fwrite 的 data ptr）
  2. 把 saved RBP 換成 0x427d50，再跳一次

Stage 2 從 0x427038 寫下去會把 0x427040 的 flag 洗掉，所以 Stage 3 第一個 gadget 就是 load_flag()，把 flag 重新讀回 0x427040。

這次寫到 0x427d00：

跑起來：

  1. pop rbx/r12/rbp ; ret：拿到 rbx=0x80、rbp=0x427218
  2. load_flag()：把 flag 補回 0x427040，它有自己的 prologue/epilogue，rbp 保留
  3. 0x404558：fwrite(flag, 1, 0x80, stdout)，flag 噴出來

噴完它會 check fwrite 回傳值對不對然後 throw system_error，但 main 開頭就 setvbuf(stdout, _IONBF)，flag 早就送出去了，crash 不影響結果。

Exploit:


FLAG: AIS3{f4k3_fl4g_1s_4ls0_4_fl4g}

賀，終於打完了。 🥳
